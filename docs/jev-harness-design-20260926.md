# Habit：一个 System One 系统

> 本文设计的是一个**独立系统**，不是 harness 的一个功能。它可以单独使用，也可以作为
> harness 的底层 System One。Jev 是它的一种底层实现，不是它的抽象。
>
> 指纹侧的断言在 [judge](../judge/README.md)，与本文的关系见 §9。

## 结论

传统 harness 是一个**没有 System One 的 System 2**：所有判断要么由 L2 做，要么根本没在做——被正则、阈值和字符串相等顶替。

System One 不是给 harness 加的一层，是**被编译的判定**：L2 在工作中反复做的那些判断，重复到形状已知，于是可以脱离 L2 运行。

它和记忆系统是对偶的：

| | 记忆 | 习惯 |
|---|---|---|
| 做什么 | 把东西**放进**上下文 | 让东西**不必进**上下文 |
| 底层 | 存储 + 检索 | **两个模型**：一个写题，一个答题 |
| 对 L2 | 有感——它读到了召回的内容 | **无感**——判定没出现在它面前 |
| 方向 | 加法 | 减法 |

所以叫 `habit`：记忆存"我知道什么"，习惯存"我不必再想什么"。

**三个概念、两个端口、一条规则、零个自由参数。**

## 1. 不可约前提

| | 前提 | 性质 |
|---|---|---|
| P1 | 推理是序列到序列的函数；一轮里模型知道的一切都在序列里 | 机制 |
| P2 | 输出自回归（串行、最贵、无缓存）；输入按前缀匹配 | 机制 |
| P3 | thinking 是生成出来的 token，按 output 计价，且默认留在前缀里 | 机制 + 当前 API 行为 |
| P4 | 存在一种便宜的类型化判断，但它的概率**没有在你的分布上校准** | **产品事实，不是机制** |

由 P4 的性质得一条铁律：

> **任何依赖 P4 数值的设计，必须带一个测量，不能带一个常数。**

### L1 / L2 按能力定义

| | 能做什么 | 代价 |
|---|---|---|
| **L2** | 产生**新的**符号序列 | 慢、贵、输出留在前缀里 |
| **L1** | 从**事先给定的**有限集合里选一个 | 快、约等于免费、不产生 token |

只有这一条差别。四个推论全是强制的：

1. L1 不能给自己出题 ⟹ **题只能由 L2 写**
2. 同一道判定两边都能答 ⟹ **一致率是免费的**
3. L1 不产生 output token ⟹ 短路省掉的正好是 L2 的输出
4. L1 不能解释 ⟹ **审计靠记录，不靠理由**

推论 1 是这套能自转的原因：**编译器就是 L2 自己。**

## 2. 推导

**第一步（P1 + P3）。** L2 生成的 token 分两类：**新工作**，和**重新做已经做过的判断**。后者是纯开销。

**第二步（P2 + P3）。** 重复判断付两次钱：生成时按 output 付（最贵的一档，无缓存），之后留在前缀里，每一轮再付一次。

**第三步。** 重复，所以形状已知；形状已知，所以可类型化。

> **重复性本身就是可编译性的判据。** 不需要第二个筛子。

反面同样成立：**新工作天然不可类型化，因为你事先不知道它的形状。** 所以"会不会把 L2 的推理掏空"这个担心自动消解——能被编译的恰好只有开销。

**第四步：短路的正确形态是旁路，不是注入。**

把 L1 的答案**告诉** L2（Brief、注入陈述），L2 是有感的——它知道有人给了它一个结论，而且会盲信这条陈述胜过自己读出来的东西。一条错的陈述就是毒。

正确的形态是**塑形入口**：

```
世界 ──→ [L1 旁路：塑形] ──→ 上下文 ──→ L2
```

人不会先看到原始光子、再收到一张纸条说"System 1 认为这是一张脸"。**你就是看到一张脸。** 视觉系统的计算对你完全无感。

这一步的后果：

| | 注入形态 | 旁路形态 |
|---|---|---|
| L2 | 有感 | **无感** |
| 失败模式 | 一条假陈述，L2 盲信 | 一次糟糕的检索，漏了东西 |
| 缓存 | 要设计注入信道 | 发生在入上下文**之前**，永远是追加 |
| 弃权 | 必须显式写进注入内容 | **不塑形 = 原样通过**，零代码 |

判据：

> **一条判定如果必须讲给 L2 听，它就不是旁路。**

"目标满足了吗""我试过这个吗"是**任务自省**，只能讲给 L2 听——那属于记忆或提示，不属于习惯。真正的旁路关于**材料**：哪几段相关、这两个观测是不是同一个、这条命令碰什么、这一步要多深的 effort。

**第五步（P4）。** 概率没校准，就要测。对照物是现成的：**L2 自己声明过的答案**。免费、在你的分布上、每次运行都产出。

> **替换和测量是同一个操作。**

## 3. 三个概念

```go
// Claim：L2 在工作中声明的一次判定——问什么、判成了什么。
// 绑在具体场景上，不能独立运行。
type Claim struct {
    Statement string
    Chose     string
}

// Reflex：从反复出现的 Claim 里抽出来的问题，给定了有限选项，
// 验证过可以脱离 L2 运行。
type Reflex struct {
    Statement string
    Options   map[string]Option   // 必须含"判不了"
}

// Compile：实例 → 类。由 L2 执行，因为 L1 只会选不会写。
Compile([]Claim) → Reflex
```

Claim 是**实例**，Reflex 是**类**。分成两个类型而不是一个类型加状态标志，是因为这样**未验证的东西在类型上就跑不了**：`Claim` 没有 Options，L1 根本接不了它。约定变成结构。

**Provider 不在这张表里。** 它是底层设施（§8），不是抽象。换掉 Jev 换成 Laya 或 Kev，这三个概念一个都不动。

## 4. 两个端口

调用方只认识这两个，不需要知道 Claim、Reflex、Compile 的存在。

```go
// 写：注册 L2 刚做过的判定
Register(ctx, []Claim) error

// 读：这次观测触发了哪些反射
Sense(ctx, state any) (map[string]string, error)   // 题 → 选中的选项
```

`Sense` 返回**决定**，不执行动作——动作是领域相关的（留哪几段、effort 调多少、丢哪个重复），属于调用方。系统本身完全不认识领域，这是它能独立存在的原因。

## 5. 两种用法

### 5.1 独立使用（像记忆系统一样）

手写 Reflex，直接 `Sense`。不需要 `Register`，不需要 `Compile`。

用途：任何**重复出现的有限选择判断**——日志归类、告警分级、内容路由。

代价要说清：跳过 Compile 就跳过了 §6 那两个解出来的数。晋升和退役由你负责，而 P4 的铁律不会因为你手写就失效——阈值仍然必须是测出来的，不能是选出来的。

### 5.2 作为 harness 的 System One

L2 边跑边注册，短路**自行形成**：

```
L2 工作中声明 ──→ Register ──→ Claim 日志（只增）
                                    │
                             Compile（离线、周期性、L2 执行）
                                    │  ① 聚出反复出现的
                                    │  ② 抽成带有限选项的问题
                                    │  ③ 用日志里 L2 自己的答案验证
                                    ▼
                              Reflex 集合 ◄─── 持续抽样；保持率掉了就移出
                                    │
观测 ──→ Sense ──→ 塑形 ──→ 上下文 ──→ L2（无感）
```

**"之后不再需要 Claim"的准确机制**：不是禁止 L2 声明，是**那个判定不再出现在它面前**。L2 原来会声明"我在判这 48K 里哪几段有用"；编译之后它收到的就是 1.2K——那个判定对它来说不存在了。不是被压制，是 moot。

**不需要看见 thinking。** 声明是显式输出，不是内部推理。thinking display 默认 `omitted`、开了也只给摘要、raw CoT 任何模型都不外露——这条限制整个绕开了。

## 6. 自转：两个解出来的数

一旦出现"一致率到 0.95 就晋升"这种人挑的数，就不自转了。

但 L2 是随机函数（P1）——**它和自己也不完全一致**。同一情境重放两次，结论会变。这个自洽率免费可测，而且是唯一诚实的标尺：

> **晋升**：L1 在历史声明上与 L2 的一致率 ≥ L2 与自己的重放一致率
> **退役**：持续抽样，上式不再成立

你没有理由要求替代品比被替代品更稳。参照物始终是日志里 L2 自己写下的 `Chose`。

**采样从不停。** 晋升只是把双跑率从 1 降到 ε，不是切换模式。因为一直在测，测量不会过期，所以不需要时间戳、不需要"训练完成"标志。

**没有置信度阈值。** 弃权已经是一个选项（每条 Reflex 构造上必含"判不了"），而阈值那套建在一个**在 0.3–0.8 中段最不可靠**的数上（§10）。两套机制做同一件事，砍掉弱的那套。

### 自愈

Reflex 移出 → 塑形不再发生 → 原始观测流过去 → 判定重新出现在 L2 面前 → L2 又开始声明它 → 攒够了重新 Compile。

**没有恢复逻辑。** 系统的降级路径就是它的正常路径。

## 7. 一条规则

> **未答即原样。** 没有 Reflex、或弃权——`Sense` 返回空，调用方什么都不做，行为和没有这个系统时逐字节相同。

在旁路形态下这不是一条要维护的约定，是**物理事实**：塑形发生在观测入上下文之前，不塑形就是原样通过。因此不需要升级机制、不需要唤醒判据、不需要兜底逻辑。**失败恒等于不启用。**

## 8. 底层设施

以下全部是设施，不是抽象。换掉它们，§3 的三个概念一个都不动。

**Provider。** L1 的实现。`ID()` 标识端点和模型——**它一变，所有 Reflex 的验证作废**，回到 Claim 日志重来。候选：Jev（托管）、Laya（421M，Apache-2.0，本机，含多语种变体）、Kev（实现同一 `/v1/systemone` 契约，SDK 可直接指过去）。

**只增。** 缓存按前缀匹配，中段编辑使其后全部失效；编辑过的历史现在还可能直接 400（preserved thinking 的 history-editing check，2026-08-31 之后创建的账号）。旁路形态天然满足：塑形在入上下文之前。

**Claude Code 的既有实践可直接引用**，不必自己论证：`<system-reminder>` 追加而非改写历史；plan mode 用常驻工具进出；MCP schema 用 `defer_loading` 存根；官方对缓存中断按可用性级别告警。DeepSeek Harness 的 append-only 会话日志 + Trajectory 视图 + fork/replay，正好是 Claim 日志需要的仪器。

**模型不能换，effort 可以。** 缓存按模型隔离，无逃生口；effort 有——`{"role":"system","content":[],"output_config":{"effort":...}}` 不触发 messages 缓存失效（beta `mid-conversation-output-config-2026-07-01`，Opus 5 / Fable 5.1）。所以"这一步该想多深"是一条合法的 Reflex。

**经济学。** thinking 按 output 计价且留在前缀（P3），所以短路省两样：生成时的 output token（最贵一档、无缓存）+ 此后每轮的前缀增长。参考量级：Opus 5 $5/$25 每 MTok，Sonnet 5 $2/$10；缓存读约 0.1×，写 1.25×（5 分钟）/ 2×（1 小时）；Jev $0.042/M，输出免费。

## 9. 边界：旁路 ≠ 新权威

§1–§8 整套只对一种东西成立，必须和另一种分开：

| | 旁路 | 新权威 |
|---|---|---|
| 做什么 | 替换掉**已经在发生**的判定 | 做一件**原本没人在做**的判断 |
| 有对照物吗 | 有——L2 的声明 | 没有 |
| 怎么定阈值 | 噪声底判据，免费 | 真标注，要花钱 |
| 失败时 | 退回原状 | 产生一个原本不存在的后果 |

**`judge` 的 `presence` 是第二种。** 规则引擎命中之后，原本没有任何东西在判"这个产品是不是真的在跑"。两个后果：

1. `judge.New` 默认的 `MinConfidence = jev.DefaultMinConfidence`（0.3）没有依据，**也不可能通过一致率取得依据**——没有"原来的做法"可比。而 0.3 恰好落在 Jev confidence 最不可靠的 0.3–0.8 中段下沿。
2. `presence.go` 里 `Refuted → Rejected` 删掉了规则引擎的命中，**弃权或出错不退回原样，而是丢召回**——直接违反 §7。指纹场景里召回损失是静默的。

两条路都行：改成退回（`Rejected` 降级为"标记待审"），或者承认它是新权威、用真标注给它有依据的阈值。不能一边按 System One 设计、一边行使权威。

真标注已经在仓库里：`.judge-data/product-authenticity/` 的 17 份带标签部署响应，SHA256 已固定。

## 10. 已知未解决与风险

1. **Projection —— 唯一会随规模真正崩掉的一处。** 每条 Reflex 喂哪段 state：64K 总 / 32K 单问上限、每页 40 条 Claim、8 个产品版本，随运行时变化，**且没有明确归属者**。试过把它收进抽象（让 Reflex 自带 `Needs`），砍掉了——今天手写截断能跑。但它是最弱的工程点。
2. **抓不到系统性偏差。** 噪声底判据只保证"不比 L2 更差"，不保证对。L1 和 L2 可以一致地错，而一致的错看起来像确证。
3. **标定不可移植。** 独立测评：公开 benchmark ECE 0.024–0.032，自建分布 0.107（噪声底 0.024）；一篇 pentest harness 论文在自有评估集上测得 Jev ECE 0.246。confidence **两端可靠、0.3–0.8 中段最不可靠**。这是 §6 砍掉阈值的经验依据。
4. **无内省。** L1 不给理由，可审计性只能靠记录（题、证据摘要、选项、动作），不能靠解释。
5. **CJK 精度。** 本仓库目标大量是中文 web 资产，需专门留中文样本。
6. **早期访问。** 无论文、无开放权重、payload 形状可能变。生产必须钉版本，不用 `jev-latest`。
7. **唯一的端到端对照数据**来自一篇 pentest harness 论文（单次运行，作者自陈不具统计效力）：墙钟 32m12s → 26m53s，findings 16 → 18，**但场景命中 10/13 → 9/13**。方向上支持省墙钟，不支持完成率不降。

## 11. 术语

**启用**：`habit`（系统）、`Claim`（L2 声明的一次判定）、`Reflex`（抽出来的类）、`Compile`（实例→类）、`Register` / `Sense`（两个端口）。

**退役**：`Verdict`、`Is` / `Pick` / `IsMany` / `IsAll`、`Brief`（含 A1/A2 双写）、`Groove`、`Startle`、`Precedent`、`Impression`、`Floor`、`MeasuredAt`。

**从未启用**：Sieve、Assay、Attest、Ledger、Rung、SiftAct、Understudy、Harvest、CoDE。

对不等于现在就该有名字；命名纪律也需要停止条件。

| 类型 | criteria | 返回 |
|---|---|---|
| `noul` | 可选，`true`/`false` 各自的描述 | `noul`，0–1 概率，**不是布尔**；**无 `confidence`** |
| `choice` | 选项→描述的 map，**最多 255 项** | `choice` + `probabilities` + `confidence` |
| `score` | **2–10 个**有序等级描述的数组 | 加权 `score` + `legend` + `probabilities` + `confidence` |

**本仓库只用 `choice`**（客户端只解码 `answer.Choice`，缺 `confidence` 直接报错）。这是个有意的选择：因为只用 choice，"判不了"才能是一个**真正的选项**而不是特殊返回值。

**已知坑**：`instructions` 与 `criteria` 自相矛盾会明显拉低质量。Compile 阶段的不一致样本最容易暴露这类规约错误。

**与本仓库现状的差异**：

- Jev 客户端与合约已迁出本仓库，现为独立模块 `github.com/chainreactors/utils/jev`；`judge/jev/` 与 `judge/page.go` 均已不存在。
- `cmd/judgeeval` 默认 `-rps 15`（上限 100），相对 1,200 req/min 偏保守。
- 分页预算散落在 `judge/presence.go`（40 条）与 `judge/version.go`（`maxVersions` 40、`maxVersioned` 8），**没有对 64K/32K 做整体校验**——即 §10 风险 1。
- `utils/jev` 现在把旁路侧和权威侧混在一个包里（`Ruling`、`Resolve(ruling, minConfidence)`、`Outcome` 的三个真值属于权威侧）。这是 §9 那条分界在代码里的位置。

## 附录 B：修订记录

### 2026-09-27 v4 —— System One 成为独立系统

**轴变了。** v3 沿着"一次调用的数据流"组织（Claim → Ruling → Resolve → Outcome）；本版沿着"一个判定从每次都做变成不必再做"组织。前者是实现细节，后者才是这套东西存在的理由。

**减法**：

| v3 | 去向 |
|---|---|
| Brief（尾部全量 / 增量入历史）、`role:"system"` 注入信道、`clear_at` | **全部退役。** 旁路形态下没有要注入的陈述（§2 第四步） |
| 「弃权必须显式出现在注入里」 | 退役。不塑形 = 原样通过，物理事实 |
| `Groove` / `Startle` / `Precedent` / `Impression` | 退役。分别塌进 Reflex、弃权、Reflex、一个单字段返回值 |
| `Floor` / `MinConfidence` / `MeasuredAt` | 退役。弃权已是选项，阈值那套建在最不可靠的信号上；持续采样使时间戳多余 |

**加法**：

1. **L1 / L2 按能力定义**（§1）——一条差别推出四个推论，取代 v3 的散列前提。
