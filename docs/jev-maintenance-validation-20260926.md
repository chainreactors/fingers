1. 审计五个内置 HTTP 目录：fingers、goby、ehole、wappalyzer、fingerprinthub；再检查别名表及加载后的 fingers 运行时目录，记录 SHA256。八个候选在初始审计范围均无同名/显式别名产品。
2. 人工依据证据组织产品正反例；Jev 从响应中提取的候选里选择名称和版本，Go 代码生成原生规则。使用普通 `Positive`，没有调用 `PositiveVersion` 向真实评估的生成器喂标签版本。
3. 导出 YAML 后重新加载、编译，验证训练匹配及版本；用训练主机以外的正反例测试。相同主机、同一运营方组及重复内容被隔离。
4. 候选至少具备两个独立正例主机组、五个独立反例主机组；身份和版本验证均无错漏才允许进入增量库。
5. 调用 `engine.Fingers().LoadFromYAML(...)`、`engine.Compile()`，用真正的 `DetectContent` 重放全部 69 份响应。检查新产品、版本、已有命中和已有非空版本。
6. 用加载后的库再运行清洗和版本补全，验证重复维护去重；最后严格离线重放，缓存未命中即失败。

## 真实数据暴露的问题与修复

- **共享基础设施被学成应用指纹**：初版 IT Tools 在测试集有 6 个误报；Docmost、Linkwarden、Karakeep 分别有 9、8、6 个。规则曾选用 Cloudflare 或通用安全头。现在应用候选头必须带有目标产品身份，普通部署环境特征不能独立成为应用规则。
- **年份版本与 generator 名称**：SearXNG 的 `2026.9.23+3cd69d30e` 被旧模式截断或混进产品名称。现在保留四位年份和后缀，以 generator 声明生成稳定识别及版本规则，可跨定制标题复用。
- **版本远离产品名**：Wakapi 版本在静态资源参数和页脚。新增带产品身份约束的版本正则；身份与版本在同一个正则中结合，避免原生匹配器的 OR 语义造成无约束版本命中。
- **加载后清洗回归**：最初重跑发现 IT Tools 两个真命中被删，SearXNG 文档被错误召回并填入版本。补充页面 description 证据，明确静态浏览器应用和文档主题的不同语义后，这三个具体问题均消除。
- **重复收录与样本计数**：`-library` 归档并加载已有扩展库；运行时目录参与查重。相同主机名或运营方的交叉分组连通后只计一次。

初始失败保留在 `run-01`，加载后清洗失败保留在 `run-05-with-library`。这些独立主机测试集在修复中被重复使用，最终结果属于回归验证，**不是未经调试使用的外部盲测准确率**。
